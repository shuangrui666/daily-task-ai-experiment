# 人机校验规则与执行清单

**版本：** 1.0  
**建立日期：** 2026-11-23  
**适用任务：** 对同一批 10 个文件执行批量重命名  
**实验状态说明：** 本文定义交付时可执行的校验规则；不表示这些规则已在原 A1–A3、B1–B3 实验过程中全部执行。

## 1. 标准命名规范

统一格式：

\`YYYY-MM-DD_类别_主题.扩展名\`

示例：\`2026-10-17_笔记_英语.docx\`

- 日期：使用四位年、两位月、两位日，且必须是真实有效的日历日期。
- 类别：只能是 \`作业\`、\`笔记\`、\`截图\`、\`资料\`。
- 主题：根据原始文件名、文件内容或任务说明提取，不能凭空补充。
- 分隔符：日期、类别、主题之间使用 ASCII 下划线 \`_\`；日期内部的连字符 \`-\` 保留。
- 扩展名：必须与原始文件扩展名一致（包括扩展名本身）；不得因重命名而转换格式。
- 文件名不得缺字段、空字段或出现多余字段。

## 2. 自动校验（机器可检查）

| 编号 | 校验项 | 通过条件 | 失败处理 |
|---|---|---|---|
| V01 | 文件数量 | 输入 10 个、输出 10 个 | 停止验收，检查遗漏或多出文件 |
| V02 | 日期格式 | 日期符合 YYYY-MM-DD | 标记日期格式错误 |
| V03 | 日期有效性 | 年月日是实际存在的日期 | 标记待确认，不自动猜测 |
| V04 | 字段结构 | 拆分后恰为日期、类别、主题三个字段 | 标记结构错误 |
| V05 | 类别白名单 | 第二字段属于四个允许类别 | 标记类别错误 |
| V06 | 分隔符 | 字段之间使用下划线 | 标记分隔符错误 |
| V07 | 扩展名 | 输出扩展名与对应原文件一致 | 标记扩展名变化 |
| V08 | 目标名唯一 | 10 个目标文件名无重复 | 标记重名冲突 |
| V09 | 一一对应 | 每个输入文件恰有一个目标名，每个目标名仅对应一个输入 | 标记遗漏、重复或错配 |
| V10 | 文件存在性 | 重命名后目标文件实际存在 | 标记执行未完成 |

日期正则只能用于初筛；还必须使用日期解析验证日历有效性。扩展名检查应与每个原文件逐一比较，不能只检查是否属于某个固定扩展名列表。

## 3. 人工语义复核（机器不能单独判定）

| 编号 | 人工检查项 | 判断依据 |
|---|---|---|
| H01 | 日期是否正确 | 原始文件名、文件内容、任务记录；如年份由实验者补充，需明确标注依据 |
| H02 | 类别是否正确 | 文件实际用途和内容，而不是只看某个关键词 |
| H03 | 主题是否准确 | 能否追溯到原文件名或内容，是否改变原意 |
| H04 | 歧义是否处理 | 日期、类别、主题无法确认时标记“待确认”，不得猜测 |
| H05 | 输出是否忠实 | 不得把资料误判为作业，或把学科名称当成类别 |

学科名称（如英语、数学、Python、数据库）可以作为主题，但不能代替类别。类别判断不能只依赖文件名关键词；必要时打开文件核对内容。

## 4. 人机分工流程

1. 建立原始文件清单，记录原文件名和扩展名。
2. 人工或 AI 生成候选新文件名；AI 只提供建议，不代表已经执行重命名。
3. 建立“原文件名—候选新文件名”映射表。
4. 运行 V01–V10 自动检查。
5. 对机器未能判断的 H01–H05 项目进行人工复核。
6. 所有错误先记录，再决定是否修正；修正后重新执行检查。
7. 只有自动检查通过且人工复核通过，才标记为“最终验收通过”。

## 5. 错误记录与修正原则

每条错误至少记录：实验轮次、原始文件名、原始输出名、预期名称、错误类型、违反规则编号、证据路径、复核状态、修正后名称（如有）。

**数据保全要求：**
- 原始 AI 输出、人工原始结果、计时记录和原始证据不得覆盖或删除。
- 修正结果应另存为独立字段或独立文件，并保留修正前后对照。
- 不得把事后制定的规则描述成原实验当时已经执行的步骤。
- 不得把建议性抽查比例写成已执行事实。

## 8. 本次实验结论边界

本仓库已有的历史结果为：人工组 A1–A3 共 28/30 正确（93.33%）；AI 辅助组 B1–B3 共 0/30 正确（0%）。历史结果来自各轮现存审计材料，且 A 组文件名审核与 B 组原始 ZIP 审计的证据载体不同，解释结果时必须保留这一限制。

本规则用于规范后续复核和解释已有错误，不回写或改变历史实验准确率。
